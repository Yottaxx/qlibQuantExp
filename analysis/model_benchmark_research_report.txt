For a two-expert router, normalized entropy is approximately
H(g) / log(2), where H(g) = -sum_i g_i log(g_i).
If H/log(2) is near 1, the gate is close to uniform. If it is near 0, it is near a hard expert choice.

- entropy_norm is often 0.80 to 0.95.

3. Code-derived model logic

3.1 Data and target
The workflow builds a daily cross-sectional stock ranking task. The label is a future return over the configured horizon, and the default context length is 8. Training uses daily cross-section batches through FixedDailyBatchSampler; evaluation and prediction use DailyChunkBatchSampler. Relevant code:
- module/dataloader/sampler.py:7,37,51,53
- module/dataloader/sampler.py:66,102
- module/model_adapter.py:1099,1104,1120,2094

The sampler mismatch matters. Training fixes each daily batch to batch_size=300, using replacement if a day has fewer names, while evaluation consumes daily chunks deterministically. If a benchmark universe has occasional non-300 daily counts or missing names, the train objective sees a subtly different empirical cross-section than validation.

3.2 Regime encoder
RegimeContextEncoder is created in module/quant_moe_model.py:87. It uses external macro state if available; otherwise it builds internal regime statistics such as correlation crowding, pc1 ratio, tail activity, and drift. Relevant code:
- module/architecture/regime_encoder.py:8
- module/architecture/regime_encoder.py:48
- module/architecture/regime_encoder.py:161
- module/architecture/regime_encoder.py:180
- module/model_adapter.py:590

Let m_t be the external daily macro state and x be the sample tensor. The model computes:
r_t = E(m_t) when external macro is configured,
or r_t = E(phi(x_t)) when internal regime stats are used.

In the current config, use_external_macro=True and market_state_path=data/market_state_csi300.pkl, so the intended path is external macro state.

3.3 Tokenization, time embedding, and FiLM
Let x_{i,t,n} be stock i, lag t, factor n. Tokenization gives h_{i,t,n}. Then:
h'_{i,t,n} = h_{i,t,n} + P_t(r_i)
P_t(r_i) = e_t * exp(-lag_t / tau(r_i)) / mean_lag exp(-lag / tau(r_i))

FiLM then creates factor-specific regime modulation:
tilde h_{i,t,n} = gamma(r_i, e_n) * LN(h'_{i,t,n}) + beta(r_i, e_n)

This is not just a generic deep net. It is a low-rank interaction between regime vector r and factor identity e_n, applied before the time/factor experts. That explains why film_only creates most of the base-to-full gain.

3.4 Two-expert MoE block
RegimeAdaptiveMoEBlock is defined in module/architecture/moe_block.py:12. It computes:
- a time expert over T for each factor
- a factor expert over N for each time
- a router over the two experts, optionally conditioned on layer summary

Relevant implementation:
- router_use_layer_summary / router_mode: module/architecture/moe_block.py:26
- layer summary projection: module/architecture/moe_block.py:34
- fixed router: module/architecture/moe_block.py:87
- learned softmax router: module/architecture/moe_block.py:102
- time expert: module/architecture/moe_block.py:154
- factor expert: module/architecture/moe_block.py:163
- fusion: module/architecture/moe_block.py:169

Mathematically:
g_l = softmax(W_l [r_i; s_l] / temperature)
z_l = g_{l,time} A_time(h_l) + g_{l,factor} A_factor(h_l)
h_{l+1} = h_l + z_l + FFN(LN(h_l + z_l))

For fixed_router_05, g=(0.5,0.5). For learned routing, g depends on regime and layer summary.

The key diagnostic implication:
If learned routing gives only about +0.002 RankIC over fixed 0.5, then either:
- the two experts are not sufficiently specialized, so A_time(h)-A_factor(h) has limited useful variation, or
- the regime/router signal is not accurately estimating which expert should dominate, or
- both are true.

The gain from better routing is approximately driven by:
E[(g*(r)-0.5) * Delta_alpha(r)]
where Delta_alpha(r) is the conditional alpha advantage of time expert over factor expert. Improving this term requires better regime state, expert specialization, or router calibration. It does not require changing the loss.

3.5 Prediction head and loss boundary
After MoE layers, AdaptivePooling aggregates the last time-step factor tokens and the head emits a stock score. Relevant code:

4. What the benchmark results say

4.1 There is still improvement space
Yes, there is likely room on this benchmark, but the evidence does not point to "change the loss" as the next lever. The main reasons:

1. Full model beats base by about +0.0079 RankIC, so the architecture is extracting real signal.
2. FiLM alone explains most of the base-to-full gain. This means regime-factor interaction is valuable.
3. Time embedding alone contributes almost nothing over base in the current seed42 matrix.
4. Learned routing beats fixed 0.5 in RankIC, but fixed router has higher RankICIR. The learned router is useful but not yet robustly proven.
5. RankIC gap is large: most good runs end with train-valid gap around 0.10 to 0.14. This is too large for a mature benchmark solution.
6. Some settings have non-trivial post_peak_decay, especially film_only and cap09. The best checkpoint restores performance, but learning dynamics are not clean.
7. Larger models are not consistently better. cap06 d96/h4/ff384/dropout0.20 is strong, but d128/h8 variants do not dominate and often have worse RankICIR or larger gap.
8. Only some capacity candidates have multi-seed evidence. cap06 and full_135 need seed repeats before claiming improvement.

4.2 What is strong
- The model's regime-conditioned factor modulation is valuable.
- Router collapse is not the primary failure mode; the gate remains active.
- The diagnostic harness is rich enough to identify whether a proposed change changes alpha, stability, or only portfolio turnover.
- Best current single-run RankIC is close to 0.08, which is a meaningful benchmark level for this style of Qlib-like cross-sectional task.

4.3 What is weak
- The time expert is not carrying enough unique signal by itself.
- Learned routing has not separated itself decisively from fixed 0.5.
- Capacity scaling is not monotone.
- Training RankIC is much larger than validation/test RankIC.
- Regime response exists, but regime-to-alpha alignment is weak.

The repro regime correlation file supports this: routing/time diagnostics correlate with market-state variables, but the same market-state variables have much weaker direct association with RankIC. In plain terms, the model notices regimes, but the current regime representation is not yet deciding the right alpha behavior sharply enough.

Implications for this model:

MASTER points directly at market-guided feature effectiveness and cross-time stock correlation. Your current model already has market-guided FiLM and axis-separated time/factor experts, but it does not explicitly model cross-time stock-to-stock correlation. That is a likely non-loss improvement direction.

StockMixer argues that simpler indicator-time-stock mixing can beat more complex architectures because financial data is limited and noisy. This supports testing simpler or more constrained router/pooling designs instead of only increasing d_model/n_heads.

TRA is directly relevant to your learned router. It shows the value of routing multiple trading patterns, but also emphasizes that routing is hard without explicit pattern identifiers. Your current learned router has no hard collapse, but its edge over fixed routing is small, which fits this warning.

DoubleAdapt and RevIN both push toward non-stationarity handling and local stationarization. Your model has regime conditioning, but not a full data-adaptation or reversible normalization layer. The large train-valid gap and weak regime-to-RankIC alignment make this a high-priority area.

Non-stationary Transformers warns that pure stationarization can remove useful non-stationary information; it combines stationarization with de-stationary attention. For this model, that means: normalize cross-sectional/temporal distributions carefully, but feed regime statistics back into attention/router so bursts are not washed out.

PatchTST, iTransformer, and TimeMixer all support better temporal representation before or inside attention: patching, variate/factor-token inversion, and multi-scale decomposition. Your current context_len=8 is short for a t+5 label; the weak time_only ablation suggests the temporal path needs richer structure, not a different loss.


6. Prioritized non-loss improvement directions

P0. Statistical confirmation before architecture churn
Run cap06, full_135, fixed_router_05, and film_only across at least seeds 42/43/44/45/46 with identical data, split, precision, and checkpoint rule.

Decision rule:
- Do not accept a new architecture unless mean RankIC improves by at least 0.0015 to 0.0020 and RankICIR does not degrade.
- Bootstrap by day and by seed. Treat single-seed +0.002 as suggestive, not conclusive.

Reason:
The current single best run can be explained by seed variance. The 3-seed std for cap00 is about 0.0030, larger than many architectural deltas.

P1. Improve regime state, not loss
The most plausible alpha improvement is better regime representation.

Concrete changes to test:
- Add leakage-safe rolling market realized volatility, breadth, turnover/liquidity, dispersion, and drawdown state.
- Add correlation spectrum beyond pc1: top eigenvalue ratio, eigenvalue entropy, mean off-diagonal correlation, sector-neutral crowding.
- Add lagged regime bank: r_t, r_{t-1}, r_{t-3}, r_{t-5}, summarized by a small causal temporal encoder.
- Standardize macro/regime features using train-fit statistics only.
- Orthogonalize highly collinear regime features to reduce noisy router inputs.
- Bucket diagnostics by regime quantiles and report RankIC per bucket.

Why:
The model already reacts to market states, but the reaction does not strongly align with RankIC. Better regime state should increase Cov(router decision, conditional expert advantage).

P2. Router calibration and specialization without loss changes
The learned router should beat fixed 0.5 more decisively if it is useful.

Concrete changes:
- Test bounded residual routing: g_time = 0.5 + c * tanh(a(r,s)), with c in {0.10,0.20,0.30}. This keeps routing adaptive while preventing noisy over-steering.
- Test router_temperature in {0.7,1.0,1.5,2.0}; monitor entropy, logit margin, RankICIR, and post_peak_decay.
- Test router_noise {0.0,0.005,0.01}. Noise may help exploration but can hurt a small-signal benchmark.
- Keep router_use_layer_summary=True, but enrich summary with separate time/factor summary statistics instead of one pooled vector.
- Measure expert disagreement directly: daily corr(A_time score, A_factor score), daily alpha spread by expert, and whether router weight predicts which expert wins.

Why:
If fixed routing is competitive, the router should be regularized by architecture and calibration, not by changing main_loss.

P3. Make the time path useful
Current time_only is almost base. That is the clearest architectural weakness.

Concrete changes:
- Test context_len 16 and 32 for the t+5 label.
- Use causal multi-scale/dilated temporal tokens: recent 1/2/4/8-day patches plus longer rolling summaries.
- Test PatchTST-style subseries patches over the time dimension.
- Add TimeMixer-style decomposition into short-term residual and slower trend components before the time expert.
- Keep label and loss unchanged; only change temporal representation.

Why:
With context_len=8, the model may not see enough temporal structure to justify a specialized time expert. Stronger temporal structure should increase Delta_alpha between time and factor experts.

P4. Improve factor/stock interaction
Your current architecture has time expert and factor expert, but it does not explicitly model stock-to-stock interaction inside the neural model in the way MASTER and StockMixer emphasize.

Concrete changes:
- Add a stock-mixing stage after per-stock representation, constrained to market/sector aggregates to avoid O(N^2) instability.
- Add sector/industry neutral summary tokens if sector metadata exists.
- Test market-to-stock and stock-to-market mixing, not full pairwise attention first.
- Turn on feature_tokenizer_add_factor_id and test whether explicit factor identity helps FiLM and pooling.
- Add missingness masks as inputs if factor coverage varies.

Why:
Financial alpha is often relative. A model that scores each stock with only implicit batch context may leave cross-sectional structure unused.

P5. Fix train/eval sampling mismatch
Training uses FixedDailyBatchSampler with random downsample/upsample to batch_size=300; evaluation uses deterministic daily chunks.

Concrete changes:
- Add a no-replacement daily sampler variant for training.
- If a day has more than batch_size names, split into deterministic chunks and accumulate gradients by day.
- If a day has fewer names, avoid replacement; pad/mask instead.
- Report train batch effective universe count, duplicate rate, and valid/test daily count distribution.

Why:
RankIC is a cross-sectional metric. Duplicating names in a daily cross-section changes the empirical geometry of the target and score distribution even if the loss is unchanged.

P6. Precision and optimization stability
Current grad_nonfinite/skipped rates are small but nonzero under amp_fp16.

Concrete changes:
- Repeat best configs with amp_bf16 if hardware supports it.
- Run one fp32 sanity benchmark for cap06/full_135.
- Keep gradient clipping diagnostics and compare grad norm distribution by module.
- Test EMA or checkpoint averaging; this changes inference weights but not loss.
- Test smaller weight decay/dropout grid around cap06, because cap06 dropout=0.20 looks better than nearby d96 settings.

Why:
RankIC deltas are small; mixed precision instability can consume the same order of magnitude as real improvements.

P7. Validation protocol and model selection
Concrete changes:
- Use rolling/walk-forward evaluation windows.
- Report day-bootstrap confidence intervals for RankIC and RankICIR.
- Use seed ensembles or checkpoint averaging only after single-model gains are validated.
- Track performance by volatility/crowding/tail regime buckets.

Why:
The benchmark is non-stationary. A single split and single seed can overstate progress.

P8. Data and leakage checks
Concrete changes:
- Audit market_state_shift=0 carefully. If macro state uses same-day close-derived values unavailable at prediction time, shift or reconstruct it causally.
- Verify label horizon and feature availability timestamps.
- Add train-fit-only normalization for both features and macro state.
- Add sector/industry neutralization diagnostics if metadata exists.

Why:
At RankIC around 0.08, a small timestamp leak or normalization mismatch can dominate the claimed improvement.
