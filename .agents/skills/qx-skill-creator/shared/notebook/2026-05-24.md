## Entry 1 — τ collapse is mechanical, not a learning failure

**Observed.** In every diagnostic-suite run where `use_regime_time_embedding=True` (full_135 seed42, cap06 seed42, time_only, no_layer_summary, fixed_router_05), `time_embedding/tau_range_utilization` sits between `3e-4` and `5e-4`. The auto-flagged `tau under-adaptive` bottleneck appears in `seed42_matrix_gradfix_20260430_2105/suite_diagnostic_summary.md` for the same arms. Read of `module/architecture/regime_adaptive_embedding.py:62-91`:

```python
self.tau_mlp_out_scale = float(tau_mlp_out_scale)   # default 0.01
...
tau_raw = self.tau_base + self.tau_fc2(h) * self.tau_mlp_out_scale   # *** 0.01 gain ***
tau     = F.softplus(tau_raw) + self.tau_min                          # softplus(4.489) + 0.5 ≈ 5.0
```

`tau_base = inv_softplus(tau_init − tau_min) = inv_softplus(4.5) ≈ 4.489`. Per-sample MLP contribution `tau_fc2(h) * 0.01` is `O(0.001-0.01)`. Softplus near `4.5` has derivative ≈ 1, so τ swings ±0.01 around 5.0. Prediction: `tau_p90 − tau_p10 ≈ 0.02`. Observed: `0.016` (full_135), `0.027` (cap06). **The data matches a mechanical bound, not a stuck optimizer.**

**Expected.** Going in I expected one of: (a) `time_tau_init` sitting at a flat-gradient region of the sigmoid-bounded `[tau_min, tau_max]` mapping, or (b) `detach()` / `no_grad` somewhere on the τ pathway blocking gradient flow. Neither matches the actual cause.

**Three explanations.**

1. **`tau_mlp_out_scale = 0.01` is a permanent damping that was meant to be a warmup.** The in-code comment reads *"delta starts small (LayerScale-style) to keep early training stable while allowing gradients to flow"* — implying the author intended a rampup. There is no rampup. The 100× attenuation persists for the entire 40 epochs, mathematically preventing τ from leaving a ±0.01 neighborhood of `tau_init`. This is the most likely cause.

2. **`tau_fc2` default-initializes too small.** `nn.Linear` Kaiming-uniform gives weight std `~ 1/sqrt(hidden)`. With `hidden = max(16, d_model/2) = 32 (cap06: 48)`, that's `std ≈ 0.18 (0.14)`. Combined with GELU-of-LN-of-unit-input upstream, the raw MLP output is `O(0.1)`. So even at `tau_mlp_out_scale = 1.0`, the per-sample swing would only be `O(0.1)`. Multiple compounding scales-down — not a single bug.

3. **`RegimeContextEncoder` output is itself low-information.** If `regime_embedding` carries little signal (e.g., the 4 internal-stat features fed through one Tanh-Linear-Linear MLP collapse the regime to a near-constant), then `tau_fc2(h)` will be approximately constant across samples regardless of scale. This is testable by reading `tau_fc2`'s output statistics directly during a run, or by raising `tau_mlp_out_scale` and seeing whether τ stays collapsed (rejects this) or expands (corroborates explanation 1 and rules this out).

**Next step.** File falsifier card `shared/falsifiers/tau-collapse-forensics-20260524.md` with two arms: (i) raise `tau_mlp_out_scale` from `0.01` to `1.0`, single seed-42 single run; (ii) raise to `0.1`, same. If arm (i) expands `tau_range_utilization` to `>0.05`, explanation 1 is corroborated and explanations 2–3 are not load-bearing. If both arms stay collapsed, escalate to explanation 3 (regime signal itself is constant) and design a follow-up that reads `tau_fc2(h)` std directly. Track 2 (A1 falsifier execution) is **gated** on this — the existing A1 card tests `regime_attn` vs `static_attn`, and if τ is frozen the regime conditioning has no surface to express itself through, so the falsifier would refute the wrong claim.

**Note on the existing `detach()` in `regime_encoder.py:84-92`.** Initially suspected as a culprit. Read confirms it is benign: it blocks gradient flow from `pc1_ratio` (an eigvalsh-derived scalar) back to the factor matrix `X`, so the model cannot subtly reshape its predictions to manipulate the perceived regime. `pc1_ratio` still enters the encoder MLP as a feature; the MLP can still learn to weight it. This is the correct semantics, not a bug.

## Entry 2 — τ-collapse is not a single bug; it is four compounding factors

**Observed.** A wider read of the τ pathway shows four mechanisms that each suppress τ variation; the `tau_mlp_out_scale=0.01` clamp documented in Entry 1 is the largest but not the only one.

**Mechanism 1 — Permanent 100× damping (proximal, already documented).**
`module/architecture/regime_adaptive_embedding.py:62-63, 88`. `tau_raw = tau_base + tau_fc2(h) * 0.01`. Persistent, no rampup. Magnitude of bound: ±0.01 around `tau ≈ 5.0`. *Math matches observation: predicted p90−p10 ≈ 0.02; observed 0.016 (full_135) / 0.027 (cap06).*

**Mechanism 2 — `regime_encoder.compute_internal_stats` broadcasts across the batch.**
`module/architecture/regime_encoder.py:167-176`. When `internal_use_batch_stats=True` (the project default), the 4 internal stats (`crowd_end`, `pc1_end`, `|crowd_drift|@lag=1`, `tail`) are computed **once per batch** and then `stats.expand(B, -1)` to all B samples. Per the in-code comment: *"for daily cross-section batch (B=stocks), recommended internal_use_batch_stats=True"*. **Consequence: all stocks in a single training batch see the same regime → identical τ within a batch.** The diagnostic `tau_p10` to `tau_p90` is therefore measured **across days, not across stocks**. A 0.016 spread is the entire cross-day variation of τ over the eval period.

**Mechanism 3 — Encoder terminal LayerNorm strips magnitude (corrected 2026-05-24).** **Correction to earlier draft.** `model_configuration.py:59` has `use_external_macro: bool = True` as default. The full_135 / cap06 / matrix runs all loaded `data/market_state_csi300.pkl` — a **102-dim** macro feature vector per day (7 base stats: `mean_abs`, `std`, `breadth`, `tail_2sigma`, `corr_mean_abs`, `corr_fro`, `corr_pc1_ratio` + 16 PCA components × 4 flavors {raw, d1, d5, d10} + 10 market-level aggregates: `market_ret_1d`, `market_vol_{5,20,60}`, `market_mom_{5,20,60}`, `market_dd_{5,20,60}`). The 4-stat internal path described in Entry 2's earlier draft is the FALLBACK, not the default. So the cross-day dynamic range of the regime *input* is **not** the binding constraint. The binding constraint is what survives the encoder: `Linear(102→2D)+Tanh+Dropout+Linear(2D→D)+LayerNorm`. The terminal LayerNorm re-normalizes encoder output to unit variance per-sample, **destroying absolute magnitude information** — only direction remains. This still meaningfully compresses, but starting from a 102-dim direction (vs a 4-dim direction) the variety of `regime_embedding` is much larger than I previously estimated. **Implication:** post-Mechanism-1 ceiling on `tau_range_utilization` is now estimated `[0.05, 0.30]`, not `[0.03, 0.10]`.

**Mechanism 4 — `T=8` makes the loss surface for τ shallow.** `work_flow.py:72, 129` overrides `context_len` from the config default of 32 down to **8**. Lags are `[7,6,5,4,3,2,1,0]`. The weight pattern `w = exp(-lag/tau)` differs meaningfully across τ only in `τ ∈ [1, 15]`; above τ ≈ 20 it is nearly uniform. With `tau_init=5.0`, the model starts in the middle of the useful range; ∂w/∂τ at τ=5, lag=7 is `7/25 = 0.28`, so a ±0.01 τ swing perturbs w by ≈ ±0.003 per element. After `normalize_decay=True` (which divides by mean), and downstream LayerNorms inside the MoE blocks, **the loss only "sees" τ through O(1e-3) changes in time_emb**. Gradient pressure on the τ MLP is correspondingly tiny — even if the 0.01 clamp were removed, the optimizer has weak pull to move τ in the first place.

**The compounding picture (multiplicative, not additive).**

| Source | Compression factor | Effect on observable τ swing |
|---|---|---|
| 4-dim regime → LN unit-scale | ~10× compression of magnitude info | regime_embedding directional only |
| Per-batch broadcast (Mech. 2) | infinite cross-sample compression | within-batch τ is one number |
| `tau_mlp_out_scale=0.01` (Mech. 1) | 100× | direct |
| T=8 weak loss signal (Mech. 4) | ~10× weaker gradient signal | optimizer doesn't push back hard |

Removing **only** Mech. 1 (raise scale to 1.0) cuts the dominant attenuation but leaves Mechs. 2–4 intact. Predicted outcome: `tau_range_utilization` rises by ~100× to `~0.03–0.05` (still well below 1.0; cross-day variation of `regime_embedding` is the new ceiling). This is the corroboration threshold in `shared/falsifiers/tau-collapse-forensics-20260524.md` P1.

**Implication for CSI300 vs CSI800.** Under the **default external-macro path**, swapping `market_state_csi300.pkl` → `market_state_csi800.pkl` changes the per-day macro vector, but both files have the same 102-column schema. CSI800 macro features will differ in *magnitude* and *variability* (mid-cap inclusion increases vol/crowd variation), but the encoder's terminal LayerNorm strips magnitude. So predicted CSI300 vs CSI800 difference under the same Mech-1 clamp is **smaller** than I originally said: probably <2× difference in `tau_range_utilization`, possibly negligible. The free check is therefore lower-information than I thought; CSI800 swap is still useful as a corroboration of the macro-pathway behavior but not as a clean Mech-3 isolator. **Better cleaner test:** zero out the macro and let the model fall back to internal stats (`use_external_macro=False`) — that's a real ablation of the macro-information channel.

**Implication for Alpha158 + t+5.** Alpha158 features are CSRankNorm-ed per day (per `analysis/embedding_design.md` and the value-embedding code path at `quant_moe_model.py:244`); cross-stock dynamic range is high, cross-day variation of *market-wide aggregate stats* is the relevant signal for τ. At t+5 horizon with T=8, the "useful τ" is probably small (τ ≈ 2–4, emphasizing recent 2–3 days), but the model is initialized at τ=5 and can't move. Effectively the model is locked into a particular temporal-readout pattern regardless of regime.

## Entry 3 — τ collapse does NOT cause pooling-attention collapse

**Observed.** Both `time_embedding/tau_range_utilization ≈ 3e-4` and `attention_pooling/pool_entropy_norm_mean ≈ 1.0` (i.e., uniform pool attention) are flagged together in every diagnostic run. Natural question: is one causing the other?

**Read of the pooling pathway.** `module/architecture/attention_pooling.py` defines `AdaptivePooling = α × AttentionPool + (1−α) × Mean`, where `AttentionPool` is a single `nn.MultiheadAttention` with **a learnable query parameter** `self.query: [1,1,D]` and key/value = factor-axis representations `x: [B,N,D]`. The pool ingests its input from the final layer's output. **It has no regime input. It does not see τ. It does not see `regime_embedding`. The two mechanisms are architecturally disconnected.**

**Three explanations for the apparent co-occurrence:**

1. **They share an upstream weak-gradient cause, not a direct mechanism.** Both are *decorative* architectural additions to a ranking-loss model:
   - τ depends on a regime-encoder output that's batch-broadcast and LN-normalized (Entry 2).
   - The pool attention depends on a 1-query × N-key setup (N=158, scale `sqrt(D)=8` for D=64). For attention to sharpen, the optimizer must learn a query whose dot-products with the N factor-keys span >1 nat of variation. The ranking loss (MSE on CSRankNorm-ed labels) pressures the **final stock score**, not the per-factor attention. With 158 factors, near-uniform attention `softmax(q·k_n/8) ≈ 1/N` is the entropy-maximizing default, and weak supervision doesn't move it. Identical failure mode (architecture starts uniform, has no specific pressure to leave uniform), different surface.

2. **Pooling collapse may be more fundamental.** `pool_entropy_norm = 0.99999` in full_135 and cap06 — *six nines*. This is so close to theoretical maximum that the query and keys are effectively orthogonal: `q·k_n` is dominated by noise. The terminal LN in `AttentionPooling.forward` (`pooled = self.norm(pooled)`) further normalizes — the output is dominated by the mean component `(1-α) × mean_pool = 0.3 × mean_pool` plus a near-mean attention contribution. **`pooling_alpha=0.7` is currently irrelevant**: the 0.7-weighted attention is itself near-mean, so the blend is essentially mean-pooling regardless of α.

3. **Pooling and τ would behave the same if both were given more gradient pressure.** Putting a sharper temperature on the pool attention (or making it n_heads > 1) would let it differentiate factors *if* the ranking loss can provide enough gradient to pressure differentiation. Same as τ: removing the 0.01 clamp lets τ vary *if* the loss surface around τ is steep enough to drive learning. Neither is currently learning; **fixing one will not fix the other.**

**Test.** A direct falsification of "τ collapse causes pooling collapse" is the τ-collapse-forensics-20260524 card's `unit_gain` arm: if `tau_mlp_out_scale=1.0` raises `tau_range_utilization` to ≥ 0.05 but `pool_entropy_norm` stays ≥ 0.999, the two are conclusively independent. Inverse experiment: an isolated `pool_attention_temperature` sweep at fixed `tau_mlp_out_scale=0.01` would show whether pool can sharpen without τ moving. **Both arms must respect HC-6: one belt parameter at a time.**

**Implication for the plan.** Track 1 (τ-collapse forensics) and a future Track 1.5 (pool-attention forensics) are **independent** — both should run, but **not** be bundled. Bundling would replay the macV3 monster-barring pattern (`RF-2026-05-22-01`): two structural changes through one pipeline, attribution lost.

**Side note: a softer cross-link does exist.** If τ collapses, every batch's `time_emb` is the same regime-blind shape. The time expert then processes time identically across days. Its output → factor expert input is "regime-blind in absolute level". The pool, which is fed the final-layer factor representations, would receive features whose **cross-day variation** is reduced. But the pool's attention is computed **within a sample** (cross-factor), so reduced cross-day variation does not pressure cross-factor attention to collapse — that pressure would have had to come from a regime-conditioned pool design which does not exist. Confirms: no direct causal link.

## Entry 4 — Phase 1 surprises (2026-05-27)

The 4-arm τ-scale sweep settled corroborate-strong (ledger row 31), but two observations weren't anticipated by the Phase 0.5 model.

### Surprise 1 — `scale=2.0` made the model *less* overfit

post_peak_decay dropped from baseline 0.00906 to `scale_20`'s **0.00761** (-16%), while RankIC stayed at +11bp and AnnRet became the best across all 5 configs (0.189). My pre-flight expectation was that any τ-MLP unlocking would either be neutral on overfit or amplify it (more expressive model → more potential to overfit). Three candidate explanations:

1. **τ adaptation acts as implicit regularization.** When τ varies across regimes, the model's effective "what to remember" pattern changes batch-to-batch — similar to how dropout / data augmentation forces representation robustness. The model can't memorize a single fixed temporal pattern because τ keeps shifting it.
2. **The regime-conditioned τ pulls the optimum away from a sharp overfitting minimum.** With a frozen τ, the model can sit at any sharp loss minimum; with τ moving with regime, the loss surface is averaged over a wider region (per-day τ ∈ [3.9, 6.9] at scale=2.0), and SAM-like flat-minimum effects dominate.
3. **Coincidence at single seed.** Need 5-seed mean±std before trusting (Phase 2 will check).

The `scale=5.0` arm contradicts explanation 1 partially — its post_peak_decay went to 0.0124 (+37%, borderline P2). So if τ adaptation is implicit regularization, it has a sweet spot around scale=1–2; beyond that, τ overshoots (`tau_drift = -2.687` at scale=5) and the regularization becomes destabilizing instead.

This sets up an interesting Phase 2 question: does `scale=2.0` survive 5-seed mean±std with post_peak_decay still below baseline? If yes, it's a genuine implicit-regularization finding (not at HC-1 level but worth adding to the design notes).

### Surprise 2 — Router shifts regime axes when τ comes alive

Router `time_ratio_vs_corr_mean_abs_spearman`: baseline -0.149 → scale_01 -0.364 → **scale_10 -0.477** → scale_20 -0.462 → scale_50 -0.333.

Router `time_ratio_vs_pc1_spearman`: -0.081 → -0.300 → **-0.421** → -0.416 → -0.278.

Router `time_ratio_vs_tail_spearman`: -0.31 → -0.26 → -0.24 → -0.24 → -0.29.

The pattern: as τ adapts, the router stops leaning on the tail-risk regime axis and engages PC1 + cross-stock-correlation. This is **the same pattern cap06 showed** when capacity grew (capacity 64→96 produced router_vs_pc1=-0.30, vs_corr=-0.33; ledger row 23 / row 33).

Two regime-conditioning paths in the architecture (τ-time and router-gate) appear **complementary, not redundant**:
- When τ is frozen, router can only carry tail-risk regime info on its own. Tail is the dominant single-axis spread (regime/tail_rank_ic_spread = 0.064 across all arms — invariant).
- When τ comes alive, router is "freed" to capture higher-order regime structure (PC1 + cross-stock corr).

**This refines HC-1.** Currently HC-1 says regime is structural; the new evidence is that the *structural channel* is multi-path: τ for temporal-memory adaptation, router for time/factor mixture, FiLM for per-factor amplitude. They share the same `regime_embedding` but read different aspects. Suggests future research direction: instrument the 3-path partition of regime information explicitly (which channel carries which regime axis?).

### Surprise 3 (mild) — Phase 0.5 synthetic projection systematically under-predicted at scale=0.1

Predicted scale=0.1 → ~0.001–0.004; observed 0.00539. The synthetic-trained-MLP × 3× factor (real-data adjustment) was calibrated at scale=0.01 baseline but **under-predicts at higher scales** by about 1.5–2×. Suggests the optimizer-amplification dynamic is non-linear: more headroom → optimizer pushes `tau_fc2.weight.std` harder during training. Not a problem (predictions still in right order of magnitude), but worth noting for future use of the synthetic predictor.
